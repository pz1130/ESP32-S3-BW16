BW16 + ESP32-S3 控制中心 · 面包板接线示意图（V3）

V3 变更（2026-10-01 实测修正）：UART 两根线不再接左排的 LP_I2C_SCL/SDA（=PA25/PA26，被 I2C 功能占用，LP_UART 硬件 mux 无法路由到这两个脚，接了串口无声），改为接右排的 LP_UART_RXD（第 8 根）和 LP_UART_TXD（第 9 根）——这是固件 Serial1 的默认脚 PB1/PB2。其余接线与 V2 相同。原 V2 图中「PA25/PA26 即丝印 D7/D8」的说法作废。
实物事实：ESP32-S3-DevKitC-1 与 BW16-Kit 两排引脚间距均为 22.86mm（900mil），跨不进标准 830 面包板的中槽（中槽只容 600mil = 15.24mm 器件）。所以两块板都放在面包板旁边用杜邦线跳接；面包板上只插 OLED 和你手上的「四位独立按键模块」。GND 全部汇到蓝轨实现共地。
黄 · S3 TX→BW16 LP_UART_RXD（#17） 绿 · BW16 LP_UART_TXD→S3 RX（#18） 黑 · GND / 共地（#1-4、8、13） 红 · 3V3→OLED VCC（#5） 蓝 · GPIO8→OLED SDA（#6） 紫 · GPIO9→OLED SCL（#7） 橙 · GPIO10-13→4键模块（#9-12）

OLED 的 GND/VCC/SCL/SDA 只要和它自己插的那几列对应即可，不必挨着图中位置；但 4 针顺序务必照模块丝印（常见 GND-VCC-SCL-SDA），VCC/GND 接反会烧屏。按键就是你手上的「四位独立按键模块」：排针丝印从左到右为 GND、K4、K3、K2、K1，对应四个键（左→右 = 上/下/确认/返回，即 S4/S3/S2/S1）。C1-C4 已在模块内部连到 GND，不用额外接地；如果你想让键位顺序反过来，在固件 config.h 里改 GPIO10-13 的按键映射即可，或直接对调橙线。

最容易翻车的四个点：① 共地黑线（#3、#4 两根 + 桥接）一根都不能省，S3、BW16、OLED、4键模块的地全靠蓝轨汇成一点；② BW16 的 USB 线必须是数据线（之前烧录卡死就是充电线惹的祸）；③ 两块板各自插自己的 USB 电源，不要用 S3 给 BW16 供电；④ BW16 侧接右排：S3 的 TX(17)→LP_UART_RXD（右排第 8 根），LP_UART_TXD（右排第 9 根）→S3 的 RX(18)，黄绿交叉；接反了 OLED 会一直显示「离线」，对调两根线即可。左排的 LP_I2C_SCL/SDA（=PA25/PA26）是 I2C 功能占用，LP_UART 硬件 mux 无法路由到这两个脚，千万别接那里——V2 图的 UART 接法就是错在这里。

本图按实物画：S3 引脚为 DevKitC-1 丝印顺序（图里转了 180°，IO 列朝面包板，GND 落在靠 USB 一端）；BW16 侧串口用右排丝印 LP_UART_RXD / LP_UART_TXD（即 LP_UART 默认脚 PB2/PB1），两脚相邻。首次上电调试清单见同目录 wiring.md。

V3 变更记录（2026-10-01）：① UART 两根线由左排 PA25/PA26（丝印 LP_I2C_SCL/SDA）改到右排 LP_UART_RXD/LP_UART_TXD；② 原因：LP_UART 硬件 mux 合法组合为 TX∈{PB1,PA26,PA12}、RX∈{PB2,PA25,PA13}，但 PA25/PA26 同时被 I2C 功能占用（开机初始化 OLED 时输出 I2C 波形），实测串口无法工作；③ V2 图中「PA25/PA26 即丝印 D7/D8、两脚相邻」的说法作废——那是裸模组的引脚图，与 BW16-Kit 实板不符；④ BW16 固件 serial_api.h 已删除重映射代码（同步修正）。

运维要点（2026-10-02 补充）：① BW16 每次重启（按 RST / 断电）后：网页里重新点一次「扫描」（扫描列表和选中状态都会清空），再重新选目标；② 串口失联 15 秒内 RX 看门狗自动重建串口自愈，无需碰板子；③ 高级干扰页自带「选择目标 AP」下拉框，也可在扫描页点「设为目标」；④ 扫不到手机热点时：保持热点开启（熄屏会自动关）、频段固定 2.4GHz、开完热点重新扫描；⑤ 固件已改 STA 模式启动（串口模式），AP 模式仅热点/钓鱼路径使用。
