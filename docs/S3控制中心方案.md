# ESP32-S3 控制中心 + BW16 攻击引擎（UART 桥架构）— 设计方案

> 状态：方案已设计完成，**待实施**（用户确认后从阶段 1 开始）。
> 侦察结论已验证：BW16 固件 Web API 全部动作函数可复用；Serial1(LP_UART) 可用；WiFi 直连方案不可行。

## 最终架构

```
[手机/电脑] --家WiFi--> [ESP32-S3 控制中心] --UART两根线--> [BW16 攻击引擎]
                         · Web 服务（家网络访问）            · 无热点，射频全留给攻击
                         · 1寸 OLED 菜单                     · 攻击/扫描/抓包引擎不变
                         · 4 按键本地操作
```

**为什么必须用 UART 而不是 WiFi 代理**：ESP32-S3 只有一个射频，无法既连家里 WiFi 又连 BW16 热点（双 STA 不支持）；让 BW16 连家里 WiFi 也不可行——攻击功能会频繁 `wifi_off/on` 切换射频模式，链路会一直断。UART 两根线是唯一同时满足"在家 WiFi 访问 + BW16 不开热点"的方案，且 BW16 固件 Web API 的全部动作函数可以直接复用。

## 一、BW16 侧改造（build_src/BW16-Tools）

1. **启用第二串口 Serial1（LP_UART）**：修改核心 `variants/rtl8720dn_bw16/variant.h`：
   `SERIAL1_TX=AMB_D7(PA25)`、`SERIAL1_RX=AMB_D8(PA26)` —— 正是 OLED 挪走后空出的两个脚。
   调试口 PA7/PA8 不动（保留烧录+日志）。⚠️ 核心重装/修复会还原此补丁，补丁要写成脚本放进 `flash_ws/`。
2. **新增 `serial_api.h/.cpp`**（行式 JSON 协议，容忍调试噪声）：
   `serialApiLoop()` 非阻塞读命令行 → 分发到与 Web API 完全相同的函数/全局状态：
   - `ping` / `status`（攻击状态+内存+uptime，1Hz 轮询用）
   - `scan` / `scan_results`（复用 scanNetworks + scan_results）
   - `select`（SelectedVector + hs_selected_network 同步，复用 /api/targets/select 逻辑）
   - `deauth`(6 种模式：single/multi/all/auto_single/auto_multi/beacon_deauth)
   - `beacon`(random/clone/custom+频段) / `ci` / `bbh` / `dos` / `stop` / `reboot`
   - `phishing`(模板+SSID) / `phish_passwords` / `phish_clear`
   - `capture`(bssid+mode) / `capture_stop` / `capture_status` / `capture_data`(PCAP base64 分块)
3. **setup() 改动**（约 6258 行）：删除开机自动 `startWebUI()`（BW16 不再开热点）；加 `serialApiInit()`；开机扫描移除（netif 未就绪会失败），改为响应 S3 的 scan 命令。
4. **loop() 改动**：顶部（6422 行后、6481 行无屏 early-return 之前）插入 `serialApiLoop()`；新增非 WebUI 模式的抓包驱动分支（`hs_sniffer_running` 时调用 `deauthAndSniff()`/`deauthAndSniff_update()`——目前它们只在 web_ui_active 分支 6470-6478 被驱动）。攻击引擎（deauth 6 种模式、advanced attacks 15ms 节流）本来就在这些分支之前轮询，无需改动。
5. BW16 自身 Web UI 代码全部保留（不再自启），将来想临时开热点仍可加串口命令或改回。

## 二、S3 侧新建工程（s3-controller/，Arduino-ESP32 核心）

1. **环境**：arduino-cli 安装 `esp32:esp32`（含 S3 支持，首次下载较大 ~1.5GB）；库：ArduinoJson、U8g2。
2. **文件结构**：
   - `config.h`：家里 WiFi SSID/密码、全部引脚宏、OLED 驱动开关（SSD1306/SH1106）、UART 波特率
   - `bw16_link.h/.cpp`：UART JSON 客户端（请求 id 匹配响应、超时重试、事件接收、PCAP 分块接收）
   - `web_api.h/.cpp`：**暴露与 BW16 Web UI 完全同形的 REST 端点**
     （/api/status、/api/scan、/api/scan-results、/api/targets/select、/api/deauth/start、
     /api/beacon/start、/api/ci|bbh|dos/start、/api/phishing/*、/handshake/*、/api/reboot...），
     内部翻译成 UART 命令 → **BW16 的 WEB_ADMIN_HTML 前端几乎零改动复用**，
     浏览器体验与现在一致，只是访问的是 S3 的 IP
   - `oled_ui.h/.cpp`：U8g2 菜单（状态页 / 扫描列表选目标 / 攻击开关 / 钓鱼 / 抓包 / 停止全部 / 重启），4 键 = 上/下/确认/返回
   - `buttons.h/.cpp`：4×GPIO INPUT_PULLUP + 消抖
3. **默认引脚**（config.h 可改，按 DevKitC-1 设计）：
   - UART1：S3 TX=GPIO17 → BW16 RX(PA26)；S3 RX=GPIO18 ← BW16 TX(PA25)；**两板共地**
   - OLED I2C：SDA=GPIO8、SCL=GPIO9（3V3/GND）
   - 按键：GPIO10(上) / 11(下) / 12(确认) / 13(返回)，另一端共 GND
4. **供电**：两块板各自独立 USB 供电（BW16 攻击时功耗大，务必稳定——v3.0 官方警告的教训）。

| 1 | BW16 串口命令固件（variant 补丁 + serial_api） | 按现有 Burn+RST 流程烧录，串口终端手测 ping/scan/status |

## 四、已确认的关键事实（侦察结论，可直接引用）

- BW16 `loop()`（6421-6666 行）是非阻塞轮询模型；串口命令层插在 6422 行后、**6481 行 `if (!g_hasDisplay) return;` 之前**即可覆盖所有模式（钓鱼 web_test_active 分支 6483、快速抓包分支 6492 也各有 return）
- Web API 全部动作（deauth 6 模式、beacon 3 种、ci/bbh/dos、钓鱼、抓包状态机）都是"置全局状态 + loop 轮询执行一步"，串口层直接复用，无并发风险
- deauth 底层：`g_deauthState` + `processXxxAttack()`(4103-4637)；advanced attacks：`g_advAttack` + `executeXxxStep`(7953-8025)；抓包状态机：handshake.h 的 `deauthAndSniff`(1021)/`deauthAndSniff_update`(1073)，60s 超时，完成后 `generatePcapBuffer()` → `globalPcapData`
- 扫描：`scanNetworks()`(2111) 阻塞版（最长 2.5s）；`wifi_scan_networks` 本身异步
- BW16 Serial1（LP_UART）波特率可调（variant.h SERIAL_TWO_UART_MODIFIABLE_BAUD_RATE=1），PA25/PA26 是合法引脚组且当前完全空闲（原 OLED 用脚）；PB1/PB2 默认脚连着板上 USB 芯片，避开
- 调试刷屏（208 处 Serial.print + 核心非阻塞 accept 的 [ERROR]）都在 PA7/PA8 调试口，不进 S3 链路
- BW16 开机自动开热点在 setup() 6258-6260；开机扫描 6262-6267（netif 未就绪会失败，必须去掉）
- `_write` 重定向可拦截核心 printf 刷屏（boards.txt 选 Arduino_STD_PRINTF: Disable + sketch 自定义 `_write`），备用手段

## 五、默认假设（config.h 全部可调，不影响架构）

- OLED：默认按 0.96" SSD1306 编译，SH1106（1.3" 款）留编译开关
- 按键：按 4 独立 GPIO 模块设计（每键一信号脚 + 共 GND）；若是 ADC 分压型再调整
- S3 板型：按 DevKitC-1 通用设计；其他板型只需改 config.h 引脚宏
- 家里 WiFi 账号密码：实施时填入 config.h
